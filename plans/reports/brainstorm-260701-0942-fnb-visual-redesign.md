## Problem Statement

FnB Container Caffe v2.1.0 has 20 static HTML pages (some 37K+ lines), 20+ page-specific CSS files, and no component architecture. The Bazi v5.1 design audit fixed bugs and accessibility but did not address structural CSS duplication, monolithic HTML files, or the visual mismatch between dark luxury container aesthetic and warm F&B food service expectations.

## Scout Findings

| Dimension | Current |
|-----------|---------|
| Pages | 20 HTML files (404 to index to loyalty-calculator), 3.7K–39K lines each |
| CSS | 20+ page-specific files + `brand-tokens.css` (Bazi v5.1: Navy/Chrome/Mộc) |
| Backend | Cloudflare Worker (286-line index.js) + 34 route files + D1 + KV |
| Design | Dark glassmorphism, Cormorant Garamond + Space Grotesk |
| Tests | 576 passing, 14 suites |
| Plugins | Odoo (Phase 1-3), ERPNext, Mixpost, pretix, Mautic, Cal.com, Xibo, Zalo |
| Debt | Duplicate @keyframes, 284 !important flags (reduced to ~203), no shared components |

## Chosen Approach

**Approach C: Component Architecture + Hybrid Design System**

- **Color:** Navy base (Bazi identity) + warm F&B accent palette (Warm Brown #92400E or Appetizing Red #DC2626)
- **Architecture:** Component-based framework + design system as single source of truth
- **Execution:** Parallel agent batches across page groups
- **Output:** Maintained as design-system/MASTER.md with page overrides

### Why not A (Clean Slate)?
Loses Bazi brand identity. High risk of breaking existing functionality. No incremental ship path.

### Why not B (Evolve Bazi)?
Doesn't fix the root problem — 20 CSS files with duplication, monolithic HTML. Kicks the architectural can down the road.

## Architecture

### Framework: React + Vite (Recommended)

| Option | Verdict |
|--------|---------|
| **React + Vite** | ✅ Best ecosystem, component model matches FnB needs, Cloudflare Pages native support, TanStack Query for data fetching |
| Vue + Vite | Lighter but fewer food/e-commerce component libraries |
| SvelteKit | Lightest but smaller ecosystem, fewer Cloudflare templates |
| Next.js | Heavy for Cloudflare Pages, better suited for Vercel |
| Astro | Good for content pages, weak for interactive order flows |

### Backend Refactor

Keep Cloudflare Worker but restructure into Hono framework (already used in `orders-hono.js`):

- **Hono** for typed routes, middleware, validation (Zod)
- **D1** via `createServerClient` pattern (already established)
- **KV** for caching (menu, product availability)
- **No new API surface** — refactor existing 34 route files into organized modules
- **Goal:** TypeScript migration for type safety across the API contract

## Implementation Strategy (Parallel Batches)

### Batch 1: Foundation (sequential prerequisite)
- Design system generation (ui-ux-pro-max `--persist`)
- React + Vite project scaffold
- Cloudflare Pages + Workers configuration
- Brand tokens → CSS custom properties
- Core UI components (Button, Card, Input, Navbar, Footer)

### Batch 2: Revenue Path (parallel)
- Page group: Index, Menu, Checkout, Success, Failure
- Stitch generate each page design
- frontend-design implement
- ui-styling polish
- Backend: auth, menu, orders, payment routes refactor

### Batch 3: Loyalty + Marketing (parallel)
- Page group: Loyalty, LoyaltyCalculator, Referral, Promotions, Events
- Backend: loyalty, referrals, promotions, reviews routes

### Batch 4: Operations (parallel)
- Page group: TrackOrder, KDS, TableReservation, TVMenu, Checkin, Admin
- Backend: tables, reservations, checkin, cron, reports routes

### Batch 5: Info + Integration (parallel)
- Page group: AboutUs, Contact, BrandGuideline, 404
- Backend: webhooks, odoo, erpnext, mautic, mixpost, pretix, zalo routes

### Batch 6: Polish
- Responsive audit (375/768/1024/1440)
- Accessibility audit (WCAG AA)
- Performance (Lighthouse ≥ 90)
- Cross-browser testing
- Test suite migration (Jest → Vitest for Vite)

```
         ↓

         ↓

         ↓

         ↓

```

## Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| Scope creep (34 backend routes + 20 pages) | HIGH | Strictly batch by priority. Ship each batch before starting next. |
| Losing Bazi brand identity | MEDIUM | Hybrid palette. Navy base preserved in MASTER.md. |
| Framework migration breaks existing functionality | HIGH | Keep old site live during migration. Ship behind feature flag or subdomain. |
| Parallel agents produce inconsistent components | MEDIUM | Design system MASTER.md as contract. Shared component library first. |
| Test suite rewrite (576 tests → Vitest) | MEDIUM | Incremental migration. Keep Jest for worker tests, Vitest for React. |

## Acceptance Criteria

1. All 20 pages rebuilt as React components with shared UI library
2. Design system persisted as `design-system/MASTER.md` + CSS tokens
3. Navy base + warm accent palette applied consistently
4. Cloudflare Worker backend restructured (Hono + TypeScript)
5. Build passes: 0 TypeScript errors, 0 lint errors
6. Tests pass: unit + integration coverage ≥ 80%
7. Lighthouse: Performance ≥ 90, Accessibility ≥ 95, SEO ≥ 90
8. Responsive: 375px, 768px, 1024px, 1440px verified
9. WCAG AA compliance (contrast, keyboard nav, screen reader)
10. Old static site remains available during migration

## Out of Scope

- New business features (no new Odoo/ERPNext integrations)
- Native mobile apps
- Real-time WebSocket/KDS (use polling for now)
- Payment provider changes (keep PayOS, VNPay, MoMo, SePay)
- 12-pillar external tool changes (Odoo, pretix, Cal.com, etc. remain as-is)
