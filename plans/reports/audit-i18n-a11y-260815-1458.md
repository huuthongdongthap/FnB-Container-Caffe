## i18n Findings

### [HIGH] Massive gap between used keys and locale definitions
- 1,596 unique dotted i18n keys used in `t()` calls across the codebase
- 427 of those keys do NOT exist in `en.json` (or `vi.json`)
- 1,036 keys defined in locale files are never referenced in code
- Root cause: many components use `t('key.name', { defaultValue: '...' })` where the key was never added to locale files, relying entirely on the fallback string
- Recommendation: Audit all `defaultValue`/`fallback` usages, extract strings into locale files, and delete unused keys

### [HIGH] 427 missing translation keys used in code

- `audit.*` (16 keys) — AuditLogViewer component

## Accessibility Findings

### [CRITICAL] Div elements with onClick but no keyboard handler
- File: `src/pages/mobile/table-manager.tsx:146` — `<div style={confirmOverlay} onClick={() => setConfirmTarget(null)}>` — overlay backdrop
- File: `src/pages/mobile/table-manager.tsx:147` — `<div style={confirmBox} onClick={(e) => e.stopPropagation()}>` — stopPropagation on content
- File: `src/pages/mobile/waiter-orders-new-order-modal.tsx:31` — `<div style={modalOverlay} onClick={onClose}>` — modal backdrop
- File: `src/pages/mobile/waiter-orders-new-order-modal.tsx:32` — stopPropagation wrapper
- File: `src/pages/saas/dashboard/cancel-dialog.tsx:39` — `<div onClick={...}>{trigger}</div>`
- Recommendation: Add `onKeyDown` handlers (Enter/Space), `role="button"`, and `tabIndex={0}` to interactive divs, or convert to `<button>`

### [HIGH] Interactive elements missing keyboard event handlers
- 35+ files with `onClick` handlers on non-semantic elements lacking `onKeyDown`
- Key offenders (non-Button elements):
  - `src/components/home/five-zone-showcase.tsx:42` — zone tab selector
  - `src/components/stitch/StitchCheckinNew-bottom-nav.tsx:15,21,28` — navigation items
  - `src/components/stitch/StitchCheckinNew-top-app-bar.tsx:20,31` — app bar buttons
  - `src/components/stitch/StitchHeroNew-navbar.tsx:72` — reservation link
  - `src/components/stitch/StitchMenu2New-menu-card.tsx:55` — add to order
  - `src/components/stitch/StitchReviewsNew.tsx:129,146` — write review, filter
  - `src/components/stitch/loyalty-weekly-streak.tsx:78` — check-in button
  - `src/components/stitch/stitch-about-header-nav.tsx:57` — scroll to order
  - `src/components/ui/navbar.tsx:118` — mobile menu toggle
- Recommendation: For non-Button elements: add `role="button"`, `tabIndex={0}`, `onKeyDown` (Enter/Space). For Button elements: these are fine as-is.

### [MEDIUM] Semantic HTML usage is inconsistent
- 506 semantic element usages (`<nav>`, `<main>`, `<section>`, `<header>`, `<footer>`) — good baseline
- Many page-level containers still use `<div>` instead of `<section>` with `aria-label`
- File: `src/components/stitch/StitchAppLayout.tsx:29` — Good: uses `<main id="main-content">`
- File: `src/components/ui/navbar.tsx:31,39` — Good: uses `<header>` and `<nav>`
- File: `src/components/ui/footer.tsx:6` — Good: uses `<footer>`
- Missing: Many Stitch page components wrap sections in `<div>` instead of `<section role="region" aria-label="...">`
- Recommendation: Replace `<div>` wrappers with `<section>` for major content regions, add `aria-label` for identification

### [LOW] Missing `lang` attribute management
- No `<html lang="...">` switching found in the codebase
- The app serves Vietnamese content but no dynamic `lang` attribute was found
- Recommendation: Ensure `<html lang>` is set dynamically based on the active locale

### [LOW] No `aria-live` regions for most dynamic content updates
- Only 10 files use `aria-live` for screen reader announcements
- Missing from: chat widget message area, KDS order status updates, real-time menu changes
- Recommendation: Add `aria-live="polite"` to chat message container, order status indicators
